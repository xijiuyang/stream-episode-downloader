# 自动选集下载（长视频平台 · Agent 模式 · 学习参考版）

把用户的自然语言指令翻译成对脚本 `src/main.py` 的命令行调用（agent 模式），或引导用户手动交互运行。

本目录自带：`SKILL.md`（本说明书）+ `src/main.py`（抓取主程序）+ `src/ts_merge.py`（下载/合并依赖，必须和主程序放同目录，缺它无法下载）。

脚本能力：搜索关键词 → 自动选中正片入口（预约/预告/花絮卡自动跳过）→ 抓全部季与集 → 逐集下载 ts 分片合并成 mp4。断点续传、每集随机延时防风控、**抓完自动调起下载器**（防 m3u8 链接过期）。

> 注意：这是脱敏后的学习参考代码。代码里的站点选择器、URL、监听关键词都以 `**` 抽象，
> 请先把 `src/main.py` 顶部的 `HOME`、`VID_URL_PAT` 和选择器适配成你的目标站点后再跑，否则会找不到元素。

## 指令 → 参数映射（agent 模式）

| 用户指令示例 | 命令行参数 |
|---|---|
| 下载某剧全部内容 / 全部季与集 / 正片全部内容 | `--name 某剧 --index 序号 --yes` |
| 下载《xxx》最新的一集 | `--name xxx --index 序号 --eps latest --yes` |
| 下载《xxx》第3集 / 第3到8集 | `--name xxx --index 序号 --eps 3 --yes` / `--eps 3-8 --yes` |
| 更新《xxx》（只补最新更新的集） | 断点续传自动生效：重跑同命令，已抓的集自动跳过 |
| 先试下几集看看行不行 | `--name xxx --index 序号 --max-eps 3 --yes` |
| 下一整季第2季 | 搜索词带季名 `--name "xxx 第二季" --yes`，或先拿候选列表让用户指 |

参数说明：`--name` 搜索词 / `--index` 搜索结果序号(1起) / `--eps` 集数过滤(latest=最新一集；也支持 5 / 3-8 / 1,4,9-12) / `--max-eps` 只抓前N集（护栏）/ `--yes` 跳过一切交互确认（agent 必加）/ `--no-download` 抓完不自动下载。

**`--name` 和 `--yes` 必须成对出现**：缺任一个脚本以退出码 4 拒绝运行（防止卡在交互问答上挂死）。

## 同名不同类型判定协议（如"某剧"有电影版/多季/动漫预告）

1. **预告/花絮卡不用担心**：脚本层已自动剔除"立即预约"预告卡，候选列表里出现的都是可播放正片
2. **用户话里带类型词**（"电影版/第二季/动漫"）→ 和候选列表的类型标注（如"电影 · 2024"）比对：**唯一命中→直接加 `--index` 自动进**；零命中或多命中→走第3条
3. **用户没带类型词且候选不止一个** → 把候选列表（含类型标注）**原样弹给用户选**，绝不替用户猜；用户没说下几集就默认整部（全季），确认范围后再跑
4. **绝不静默选第一个候选**——同名不同型选错会白抓几十集还浪费请求次数

## 执行步骤

1. 从用户指令提取节目名与范围（最新一集/第N集/全部），按映射表拼参数。
2. 让用户在编辑器终端手动运行（脚本窗口化、可 Ctrl+C 中断，中断后已存盘/断点；在 `src/` 目录下执行）：
   ```
   python main.py --name "节目名" --index 1 --yes
   ```
3. 跟踪输出确认流程：搜索列表 → 进播放页收集集数（按季分组打印）→ 逐集"✅抓取 m3u8"→ 抓完自动调起 ts_merge.py 下载 →"下载→合并→完成 xx.mp4"。
4. 全部跑完后**分两层汇报**：抓取结果读 `抓取报告.json`（字段：show/mode/总集数/已抓取/含m3u8/失败清单/断点文件/自动下载）；下载结果看 src/ 目录里的 `第N集_标题.mp4` 成品。**抓取成功 ≠ 下载完成，两层分开说。**

## 退出码 → 你的动作

| 码 | 含义 | 动作 |
|----|------|------|
| 0 | 完成 | 读 `抓取报告.json` 分层汇报 |
| 1 | 无结果/没匹配到集数 | 告知用户；换更完整节目名重试最多1次（须先征得同意） |
| 2 | 多候选 | 把脚本打印的候选列表**原样**展示请用户选序号，带 `--index` 重跑 |
| 3 | 序号越界 | 告知候选实际条数 |
| 4 | 参数不全（--name/--yes 没成对） | 补齐参数重跑 |
| 5 | 已有实例在跑（并发拒绝） | 转述并询问排队还是放弃；**绝不杀进程、绝不手动删锁** |

手动单独跑 `python ts_merge.py` 遇到退出码5同理 = 已有下载任务在跑（下载锁）：排队等它结束，成品断点续传不会丢。

## 执行边界（铁律）

- 脚本没有任何自动/定时/后台/无头启动机制：只有**用户手动运行**才执行；断点续传（`m3u8结果_{节目名}.json`）也只发生在**下次手动运行时**。
- 用户关闭编辑器/终端、中断会话或任务 → **立即默认结束**：不后台继续、不自动重跑、不开无头补抓。
- **打开编辑器 / 双击 .py / 打开 IDE，不会触发任何运行**——脚本自身没有任何启动机制，只有被"显式调用"才运行。
- 下次用户手动给出指令时，重跑同命令即从断点补上未完成的集，已完成的集自动跳过。
- **并发故意不支持**（单浏览器接管/防风控/文件安全）：运行锁+下载锁双锁分离、原子抢锁（O_EXCL）+ PID 验活 + 残留锁自愈。两个任务同时启动时，后到的以退出码5被拒——这是保护不是故障，**串行排队才是正确用法**；每剧断点独立文件，先后抓互不覆盖。
- 连续5集抓取失败会自动熔断停止——这是防风控保护，**不要反复重跑**，先读 `抓取报告.json` 的失败清单分析原因。

## 注意事项

- 单实例锁：双开自动拒绝并报出已运行实例 PID；崩溃残留的锁下次启动自动清理，无需人工干预，也**不要手动删锁文件**。
- 别双击运行任何爬虫脚本（Windows 会把双击的 .py 直接拉起来跑）；想跑就在终端运行并盯着它结束。
- 成品命名：`第N集_标题.mp4`（多季按季分组各从1编号）；断点文件 `m3u8结果_{节目名}.json`、链接文件 `m3u8链接.txt`（每部剧独立断点）。
- m3u8 链接带签名有时效（几小时）：抓完会自动衔接下载；报"链接失效"时**征得用户同意**后把该节目的断点 json 改名备份，重跑抓取拿全量新链接（已有成品的集下载器自动跳过，不会重复下载）。
- 预约/预告/花絮卡会自动跳过；未播出剧目不在下载列表内，属正常。
- 若输出"没有可进入的节目"，让用户换更完整的关键词（如"某某剧第二季"）再跑。
- 多季剧会在一个播放页里通过季标签全部抓到，后面的同名季卡会自动跳过不重复下载。
- 成品只有 .ts 没有 .mp4 = 机器缺 ffmpeg：提示 `winget install Gyan.FFmpeg`，装完重跑 ts_merge.py 即可补转封装（不用重新下载）。
- 中途强关窗口会残留浏览器僵尸进程：先在任务管理器结束该进程组（Chrome for Testing）再跑。
