# 长视频平台自动选集下载（窗口化）

> **一句话定位**：长视频选集批量下载工具——搜索 → 自动识别正片入口 → 收集全部季与集 → 逐集下载 ts 分片合并成 mp4。个人独立开发，覆盖浏览器自动化、虚拟列表收集、流式下载、断点续传、工程健壮性完整链路。

一个基于浏览器自动化的长视频选集批量下载工具。搜索关键词 → 自动定位正片入口 → 把整部剧的全部季与集都抓下来，逐集下载 ts 分片合并成 mp4。断点续传，中途断了重跑就好。

## 为什么做这个

不是啥高深理由，就是自己看片不想一集集手动点。尤其多季剧，Season 拉了一长串，每一个都要点开、等加载、再点下一集，纯手工能点到怀疑人生。干脆写个脚本挂在那儿自动点、自动下。

这个过程踩了不少坑才稳下来。最开始直接点标题、点"立即播放"，经常落到封面页自动播花絮（封面页会自动播最新花絮，抓下来就是一段预告）。后来发现要先从卡片上找选集格子"1"直达第 1 集正片页才稳。还有集数列表是虚拟滚动，不滚到底它就只给你渲染一屏，怎么逼它补加载、怎么收集到全部集数，都折腾过很久。

## 技术原理拆解

整条链路大概是这样的：

1. **浏览器自动化控制**：用 DrissionPage 起一个真实 Chrome，全程窗口化，走 CDP 模拟真人滚轮和点击，网页把它当成真人。
2. **搜索结果卡片识别与过滤**：搜索结果里混着"预约卡""预告卡""花絮卡"，没有正片入口。脚本从卡片文字里提取"年份/类型/地区"来标注，识别有没有播放/选集格子，没有就跳过。
3. **进入正片**：优先点卡片上的"选集格子 1"（带直链）进第 1 集；找不到就降级点标题，落在封面页/花絮页还会再补救跳正片。
4. **集数列表的虚拟滚动收集**：集数面板是虚拟列表，一屏只渲染十几条。用滚轮往上顶分批补加载更早的集，再回顶从上到下扫一遍记录每条在列表里的绝对位置，据此排序。
5. **多季/多段标签分区**：多季剧集号会重名。通过识别页面上的"季标签""数字段标签(1-30/31-36)"逐个点过去，把每一季每一段的分集都收一遍，同名按正确分区覆盖。
6. **m3u8/ts 分片流式下载 + AES-** 解密**：从页面网络包里递归抓出清晰度最高的 m3u8，逐片下载 ts，`#EXT-X-KEY` 带加密就用 pycryptodome 解 AES-** CBC。
7. **merge 成 mp4**：分片二进制顺序拼接成完整 ts，再走 ffmpeg `-c copy` 无损转封装成 mp4（不重编码，秒转）。
8. **断点续传**：每抓到一集就写断点 json，重跑自动跳过已抓的；已存在且非空的分片直接跳过，不用重下。
9. **人味延时与防封策略**：等待时间、滚动幅度、每集切换节奏全部随机，模仿手速，避免固定节奏被识别。
10. **单实例锁**：`.lock` 文件防双开，有旧实例活着就拒绝新实例，避免两个脚本抢页面/抢断点文件。

## 用法

依赖：Python 3、`DrissionPage`、`requests`、`pycryptodome`（解密用），以及系统里的 ffmpeg（转 mp4 用）。

两个文件要放在同一目录。手动在终端运行：

```
python main.py --kw 某剧                   # 全部季与集（预约页自动跳过）
python main.py --kw 某剧 --mode latest     # 每季最后一集
python main.py --kw 某剧 --mode ep --ep 3  # 指定第 3 集（指定集数，第**集）
python main.py --kw xx --mode update       # 增量更新：只补新增的集
```

**注意：代码是脱敏的学习参考版**。里面用到的站点选择器（`card-title` / `sub-title` / `ep-item-row` / `ep-cell` / `#ep-list` / `#search-input`/'**'）和首页地址 `https://**.com/` 都是占位，请先把它们换成你自己的目标站点真实选择器再跑，否则会报找不到元素。
