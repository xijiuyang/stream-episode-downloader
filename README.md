# 长视频平台自动选集下载（窗口化 · Agent 模式）

> **一句话定位**：长视频选集批量下载工具——搜索 → 自动识别正片入口 → 收集全部季与集 → 逐集下载 ts 分片合并成 mp4。本版完成 **Agent 化改造**：可以被 AI Agent 用一句自然语言调度（"下载xx最新一集"），带语义化退出码协议、原子单实例锁、防挂死设计。个人独立开发，覆盖浏览器自动化、虚拟列表收集、流式下载、断点续传、并发控制、Agent 工程化完整链路。

一个基于浏览器自动化的长视频选集批量下载工具。搜索关键词 → 自动定位正片入口 → 把整部剧的全部季与集都抓下来，逐集下载 ts 分片合并成 mp4。断点续传，中途断了重跑就好。

## 为什么做这个

[](#为什么做这个)

不是啥高深理由，就是自己看片不想一集集手动点。尤其多季剧，Season 拉了一长串，每一个都要点开、等加载、再点下一集，纯手工能点到怀疑人生。干脆写个脚本挂在那儿自动点、自动下。

这个过程踩了不少坑才稳下来。最开始直接点标题、点"立即播放"，经常落到封面页自动播花絮（封面页会自动播最新花絮，抓下来就是一段预告）。后来发现要先从卡片上找选集格子"1"直达第 1 集正片页才稳。还有集数列表是虚拟滚动，不滚到底它就只给你渲染一屏，怎么逼它补加载、怎么收集到全部集数，都折腾过很久。

后来这个脚本被接入 AI Agent 定时任务，暴露出一堆新问题：Agent 不会应答交互问答（脚本会永远挂死）、读不懂 print（不知道成败）、两个定时任务同一毫秒启动会双开互踩、抓完不马上下载链接就过期。于是有了这一轮 Agent 化改造——**给 LLM 写接口和给人写接口，是两回事**。

## 技术原理拆解

[](#技术原理拆解)

整条链路大概是这样的：

1. **浏览器自动化控制**：用 DrissionPage 起一个真实 Chrome，全程窗口化，走 CDP 模拟真人滚轮和点击，网页把它当成真人。
2. **搜索结果卡片识别与过滤**：搜索结果里混着"预约卡""预告卡""花絮卡"，没有正片入口。脚本从卡片文字里提取"年份/类型/地区"来标注，识别有没有播放/选集格子，没有就跳过——这个类型标注还兼做**同名不同版本的判定依据**。
3. **进入正片**：优先点卡片上的"选集格子 1"（带直链）进第 1 集；找不到就降级点标题，落在封面页/花絮页还会再补救跳正片。
4. **集数列表的虚拟滚动收集**：集数面板是虚拟列表，一屏只渲染十几条。用滚轮往上顶分批补加载更早的集，再回顶从上到下扫一遍记录每条在列表里的绝对位置，据此排序。
5. **多季/多段标签分区**：多季剧集号会重名。通过识别页面上的"季标签""数字段标签(1-30/31-36)"逐个点过去，把每一季每一段的分集都收一遍，同名按正确分区覆盖。
6. **m3u8/ts 分片流式下载 + AES 解密**：从页面网络包里递归抓出清晰度最高的 m3u8，逐片下载 ts，`#EXT-X-KEY` 带加密就用 pycryptodome 解密。
7. **merge 成 mp4**：分片二进制顺序拼接成完整 ts，再走 ffmpeg `-c copy` 无损转封装成 mp4（不重编码，秒转）。
8. **断点续传**：每抓到一集就写断点 json（**每剧独立文件**，键带季前缀防不同季"第1集"撞车），重跑自动跳过已抓的；已存在且非空的分片直接跳过，不用重下。
9. **人味延时与防封策略**：等待时间、滚动幅度、每集切换节奏全部随机，模仿手速，避免固定节奏被识别；连续 5 集抓取失败自动熔断，宁可停也不硬跑。
10. **单实例锁（三段演进）**：第一版"先检查锁存在再创建"有 TOCTOU 竞态，同毫秒双启动双双放行；改成 `os.open(O_CREAT|O_EXCL)` 原子抢锁，互斥由内核保证；后来又发现"抢到锁到写入 PID 之间"的空锁窗口会被后来者误当残留锁删掉——补上"空 PID 只重试绝不删"。锁内写 PID + 存活检测，崩溃残留锁下次启动自愈。抓取用运行锁、下载用下载锁，**双锁分离**防止抓取进程调起下载进程时自锁死。

### Agent 化改造（本版新增）

11. **防挂死（双面防呆闸）**：Agent 无法应答 `input()`，任何交互问答都是无限期挂死点。`--name` 与 `--yes` 必须成对出现，任缺一面直接退出码 4 拒绝运行。
12. **语义化退出码协议**：0 完成 / 1 无结果 / 2 多候选待选择 / 3 越界 / 4 参数不全 / 5 并发拒绝——每个码对应 Agent 的一个确定动作，不靠猜 stdout。
13. **机器可读报告 + 两层汇报**：结束写 `抓取报告.json`（总集数/已抓/失败清单/断点路径）；约定"抓取成功 ≠ 下载完成"，抓取看报告、下载看成品目录，汇报分层。
14. **自然语言意图层（SKILL.md）**：技能说明书里写死"意图→参数对照表"（"下载xx最新一集"→`--name xx --eps latest --yes`）和同名判定协议——候选带类型标注，多候选原样弹回给用户选，**绝不静默猜测**。
15. **自动衔接**：抓完自动 `subprocess` 调起下载器，趁 m3u8 链接新鲜（几小时时效）立刻下载。

## 用法

[](#用法)

依赖：Python 3、`DrissionPage`、`requests`、`pycryptodome`（解密用），以及系统里的 ffmpeg（转 mp4 用）。

两个文件要放在同一目录。手动在终端运行（`src/` 目录下）：

```
# 交互模式（不带参数，和自用版一致）
python main.py

# agent 模式（--name 与 --yes 必须成对，缺任一个退出码 4 拒绝运行）
python main.py --name 某剧 --index 1 --yes                # 全部季与集 + 抓完自动下载
python main.py --name 某剧 --index 1 --eps latest --yes    # 只抓全剧最新一集
python main.py --name 某剧 --index 1 --eps 3-8 --yes       # 只抓第3~8集
python main.py --name 某剧 --index 1 --max-eps 3 --yes     # 先试抓前3集（护栏）
python main.py --name 某剧 --index 1 --yes --no-download   # 抓完不自动下载

# 仅下载（链接已存在时）
python ts_merge.py
```

多候选且未给 `--index` 时：打印候选列表后以退出码 2 结束（agent 拿列表问用户）。断点续传自动生效：重跑同命令，已抓/已成品的集自动跳过。

**注意：代码是脱敏的学习参考版**。里面用到的站点选择器、URL、监听关键词一律以 `**` 抽象（适配点集中在 `main.py` 顶部的 `HOME`、`VID_URL_PAT` 和各选择器处），请先换成你自己的目标站点真实特征再跑，否则会报找不到元素。

## 流程示意

[](#流程示意)

```
自然语言指令（"下载某剧最新一集"）
  ↓ SKILL.md 意图映射（agent 翻译成参数）
搜索关键词（--name）→ 候选列表（带类型标注；同名多版本原样问用户，绝不猜）
  ↓ --index
进入正片播放页（优先"选集格子1"直链，落花絮页自动补救）
  ↓
收集全部季与集（虚拟滚动补加载 + 分区标签逐季逐段点）
  ↓ --eps / --max-eps 过滤
逐集：切到该集 → 监听网络包 → 递归抓 m3u8 → 挑最高清晰度
  ↓（每集即时写断点；连续5集失败熔断；抓完写 抓取报告.json）
自动调起 ts_merge.py
  → 下载全部 ts 分片（AES 解密，断点续传）
  → 分片顺序合并 → ffmpeg 无损转 mp4
  ↓
跑完自动关浏览器、释放运行锁/下载锁
```
