# 工程日志

> 只记录两件事：遇到过什么问题、怎么解决的。按主题整理。

---

## 一、页面与入口

- **点标题、点"立即播放"都会落进花絮页** → 入口按优先级：卡片上的选集格子"1"最稳（格子带链接就直接访问）；落到封面页（URL 不含视频 id）时，主动找"正片第1集"入口补救跳转。
- **正片、花絮、预告在页面上长得一样** → 用标题格式过滤（含"第N集"且不含"预告/花絮"）；格子流程能收到 10 条以上就直接当正片。
- **全页搜"立即播放"匹配到别的卡片** → 入口必须在卡片自己范围内验证：从标题往父级爬到卡片边界，只在里面找按钮/格子。
- **集数面板的 id 每部剧都不一样，写死必挂** → 不认 id：从第一个可见条目向父级爬，锁定含"季标签 / 数字段"文字的祖先容器当面板。
- **多季多集是两层分区标签（季行 + 数字段）** → 统一流程：先抓当前页 → 逐个点分区标签、每停一处再抓一遍 → 同名去重（后到盖先到）→ 按（季序, 段序, 格子位置）排序合并。
- **鼠标悬浮的预览浮层挡住滚动** → 滚轮事件按坐标命中会中招；改 JS 直接改 scrollTop，与鼠标彻底脱钩（顺带为无头化扫清障碍）。
- **虚拟列表滚出视口就卸载卡片，直接扫只能拿到一屏** → 边滚边收集，记录每条在列表内的绝对位置；切集前先滚到目标位置让卡片重新渲染。
- **裸 click 被前端框架事件系统拦截** → 用 dispatchEvent 派发 MouseEvent，冒泡到卡片容器。
- **综艺、电影和剧集页结构不同，分支越写越多** → 三分流：有格子走格子流程；列表但无标签走列表流程；列表且有标签走合体流程（滚动收集 × 标签循环）——按页面结构归类，节目类型会膨胀、结构不会。

## 二、下载链路

- **m3u8 链接带签名，几小时就过期** → 不攒链接：每抓一集立刻下载合并。
- **播放信息藏得深，按固定路径找必挂** → 递归遍历响应 JSON 按 key 特征找；清晰度用官方档位表反查名称、按高度挑最高，同档位多条 CDN 镜像去重。
- **分片带 AES-128 加密** → 解析 EXT-X-KEY 拉取密钥解密（无 IV 时按段序号生成），再二进制拼接。
- **ts 分片不是能直接播放的 mp4** → ffmpeg -c copy 无损转封装（不重编码、秒转）；转完删除分片缓存和 ts 原文件。

## 三、稳定性与容错

- **死循环：页面渲染不出内容时，continue 没推进空转计数**，空转 500 次×1 秒，外层循环还加剧 → 每条 continue 路径都必须推进计数，所有循环带上限。
- **强关脚本窗口会残留浏览器僵尸进程**（最狠一次 21 个进程吃约 8GB 内存，机器卡死） → 脚本结尾强制关浏览器。
- **断点被串行任务洗掉**：单断点文件下，A 没跑完去跑 B，A 的进度被覆盖、重跑会重复请求几十集 → 每剧独立断点文件 + 旧格式断点幂等迁移。
- **连续失败还硬跑，越跑越容易触发风控** → 连续 5 集失败立即熔断；断点已存，稍后重跑自动续。
- **单集验证换页后失效**（面板点位失灵、后退时 history 链断裂） → 三级回退：预热切到第 2 集 → 浏览器后退重发请求 → 点位直抓兜底。

## 四、Agent 化改造

- **Agent 一调用就挂死**：脚本全是 input() 交互 → 全部换成命令行参数；参数成对校验——--yes 缺 --name、--name 缺 --yes 都以退出码 4 拒绝（防挂死要两面都堵）。
- **Agent 读不懂 print** → 结束写机器可读的 JSON 报告（总集数 / 已抓 / 失败清单 / 文件路径）。
- **成败无法程序化判定** → 语义化退出码：0 完成 / 1 无结果 / 2 多候选 / 3 越界 / 4 参数不全 / 5 并发拒绝，每个码对应一个确定动作。
- **抓完没人下载，链接放几小时就废** → 抓取结束自动调起下载器（subprocess 衔接），可用参数关闭。
- **自然语言怎么落到执行** → SKILL.md 写死意图对照表（"下载xx最新一集" → --name xx --eps latest --yes）；Agent 只做翻译，脚本只认参数。
- **同名不同版本选错，白抓几十集还费请求** → 候选带类型标注；唯一命中才自动进，多命中原样弹回给用户选，绝不静默猜。
- **预告卡混进候选** → 脚本层直接剔除"立即预约"且无播放入口的卡片。
- **抓取成功 ≠ 下载完成，混着汇报会掩盖失败** → 两层汇报：抓取看报告 JSON，下载看成品目录。

## 五、并发与锁

- **两个实例同时启动会互相抢页面、抢断点**："先查锁再创建"是 TOCTOU 竞态（两个同时通过检查就双双放行） → 改 O_EXCL 原子抢锁，同毫秒双启动也只放行一个。
- **崩溃留下残留锁挡路** → 锁里写持有者 PID；后来者验活（拒绝访问也算活着），确认死了才清理重试（限 3 轮）。
- **空锁窗口**：抢锁成功到写入 PID 之间有几微秒窗口，后来者把空锁当残留删掉等于"偷锁" → 空 PID 只重试不删，等不到就保守退出——宁可拒绝，不要双开。
- **子进程拿不到锁会自锁死**：抓取脚本调下载器时自己还握着运行锁 → 下载器改用独立锁文件，两把锁互不干扰。
- **打开编辑器 CPU 100%**（一度怀疑脚本自启） → 真相：分离运行的旧进程 + 几万个 ts 分片被疯狂索引；排除目录索引、删运行配置、关自动恢复。

## 六、工程纪律

- **重构一把梭翻车**：合并函数时把去重键改掉，集数全乱 → 大改前先存档基准版；一次只叠一个修复、跑通再加下一个；回归必须拿最复杂场景测。
- **文档和代码对不上**（说明书里的目录、文件名都过期了） → 给 Agent 看的文档当代码审，逐条对账。
- **开源要安全** → 脱敏到"跑不了"：域名 / 选择器 / 监听关键词全部占位化，与真实站点从根源脱钩。
